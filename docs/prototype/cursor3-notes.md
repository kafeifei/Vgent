# Cursor 3 Agents Window 观察笔记

从参考截图（m1–m6，未入库，只留这份文字笔记）里看到的界面模式，按下面这套重做原型时对照用。
不是像素级还原，是"信息架构和交互模式"的参照。

1. **整体是全屏三栏工作台**，不是编辑器旁边挂一条窄侧栏——这是和 2025 年老版 Composer 最大的区别：
   老版是"编辑器为主、AI 是配角面板"，Agents Window 是"AI 任务列表为主、代码是配角面板"。
2. **左栏任务列表按仓库分组**，组标题是小号 muted 的 `owner/repo` 文字，不是可折叠的树；同一仓库下
   的多个任务紧挨着排列，视觉上靠留白和组标题分隔，不靠边框分隔。
3. 任务列表每一项**两行信息**：第一行标题 + 状态指示；第二行是"正在做什么 / 什么时候完成"这类动态
   摘要，而不是固定的静态副标题。
4. **运行中的任务用实心呼吸点，等待人处理的任务用空心环**——颜色和形状都传达状态，不是纯靠颜色。
5. 顶部没有传统意义上的应用标题栏，窗口条极简，几乎只剩必要的全局切换（项目/分支、主题这类），
   大部分功能入口下沉到对应的面板里。
6. **对话里的用户消息是一个独立的圆角卡片**，视觉权重和 agent 回复的正文分得很开，不是简单的
   左右对齐气泡，也不是加左边框的色块。
7. **工具调用极度轻量化**：多数是一行文字（动词 + 目标 + 耗时/结果），没有卡片边框，读起来像日志
   而不是像"结果展示组件"；只有真正需要单独呈现的内容（文件 diff、终端块）才升级成更重的视觉。
8. **一轮对话有明确的"收尾"动作**：过程性的工具调用会被收进一个可展开的摘要行，收尾之后呈现的是
   agent 的结论性文字（类似"这轮做了什么/验证了什么"），过程和结论分层次展示。
9. **文件改动用小小的 chip 表示**（文件名 + 加减行数），不是罗列在正文里的大段文字，点击就跳转去看
   具体 diff。
10. **审查/提交这类"收口"动作被固定在输入框上方，常驻显示**，而不是散落在每一条消息末尾——无论
    产生了多少轮改动，"现在一共改了什么"永远在同一个位置。
11. **上下文占用用一个小圆环体现**，不是进度条也不是纯数字，环形在小尺寸下比条形更省地方，且天然
    是"占比"的隐喻。
12. **右侧面板是图标 tab，不是文字 tab**：变更、文件、终端、计划、队列这几类切换靠图标 + 选中态
    下划线，面板整体更像"检查器/侧信息面板"而不是"另一个主内容区"。
13. **"计划"以文档的形式呈现**，有标题、说明段落、任务清单，读起来像一份 PRD 里的任务分解，而不是
    机械的 to-do 卡片列表。
14. **提问交互是"一问一页"**：一次只显示一个问题，选项编号化，靠前进/后退切换到下一个问题，
    而不是把所有问题一次性平铺展示。
15. **空状态是"配置 + 输入"而不是"欢迎语 + 建议"**：先选清楚在哪个仓库、什么运行位置、哪个分支，
    再输入目标，强调"开始一个任务前先确定运行环境"这件事本身就是核心交互。
16. **侧栏可以收缩到只剩图标条**，收缩后仍然保留"新建任务"和"每个任务的状态"两个最核心的信息，
    不是收缩了就完全消失。
17. 整体的信息密度比传统聊天界面更紧凑，但靠留白和文字层级（而不是边框）来分隔内容区块——
    边框/卡片是"稀缺资源"，只用在真正需要强调独立性的地方（审批、提问、diff、终端）。
