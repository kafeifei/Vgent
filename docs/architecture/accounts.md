# Accounts

Accounts are logins Vgent can use: Claude, Codex and GitHub, any number of each (`packages/server/src/accounts/`). The account service is the one projection every surface reads — the account page, the sidebar panel, the quota card, the provider page, the model lists and the engines. Credentials stay with their owners; `accounts.json` in the data directory keeps only which accounts exist, their order of addition and the uses switched off.

| Platform | Where one account's login lives | Uses |
| --- | --- | --- |
| Claude | The machine's own login (`~/.claude`, keychain `Claude Code-credentials`), or a Vgent-owned config directory `<dataDir>/accounts/<id>` passed as `CLAUDE_CONFIG_DIR` — Claude Code then keeps the login in keychain `Claude Code-credentials-<sha256(dir)[:8]>` | models |
| Codex | The machine's `CODEX_HOME` (default `~/.codex`), or `<dataDir>/accounts/<id>` as `CODEX_HOME` | models |
| GitHub | One item per account under keychain service `dev.vgent.remote.<data dir digest>`, account name = account id (the first keeps `github`, where the single remote login used to be) | models (Copilot), remote access |

`models` switches an account's models in or out of every engine that runs them: the engine is the model's business, never an account setting. Records written by build 196, which had one switch per engine, lose those keys on read.

Ids: the machine's logins are `claude` and `codex`, the first GitHub account `github`; every other account is `<kind>-<8 hex>`. A model on a platform's first account keeps its old spec (`sonnet`, `gpt-5.5`, `codex-subscription:gpt-5.5`, `github-copilot:<id>`); any other account prefixes it: `@codex-1a2b3c4d:gpt-5.5`. Engines split the prefix off (`splitAccountSpec`) and run with that account's `CLAUDE_CONFIG_DIR`, Codex home or Copilot access. Model keys, hidden-model switches, 提供商排序 keys (`subscriptionKey`) and picker headings are per account, so two accounts of one platform are two sources.

A Vgent-owned Claude directory links in `~/.claude`'s user content — settings, CLAUDE.md, agents, commands, skills, plugins, hooks, output styles — and the conversation state (`projects`, `file-history`, `todos`, `plans`), so `claude --resume` finds a session whichever account ran it. The CLI's own `.claude.json` (the signed-in account) and `backups` stay per directory; sharing `backups` makes the CLI refuse to start.

Sign-in runs the vendor CLI (`claude auth login --claudeai`, `codex login`) in the target directory and reports the authorization link it prints; GitHub uses the device flow. A new login goes to the machine's slot while that is signed out, else to a new directory. A task's error action and quota card always pass its account id when signing in again, even if the expired login no longer appears in the snapshot; recovering a removed Vgent-owned account restores that same id. Every completed Claude or Codex login, including the machine's slot and re-login, checks its identity (Claude email + org, Codex email + ChatGPT account) against the other accounts and undoes a duplicate. The same GitHub user signing in again renews that account. Sign-out asks the CLI to sign out of that directory, then removes a Vgent-owned directory; signing out of the machine's login signs the terminal out too.

Copilot: a GitHub login is exchanged for a Copilot token that lasts minutes (`copilot.ts`), which also names the account's own API host (`endpoints.api`, e.g. `api.individual.githubcopilot.com`); every request goes there with the client headers, `X-Initiator` (`agent` when the last input is a tool result) and an effort level the model's list offers (`fitLevel`: the most it offers up to the one asked for, none for a model with none). The model list keeps, per model, the protocols from `supported_endpoints`, the effort levels, the maker and the prompt limit (`max_prompt_tokens` — the context window counts the reply too). An engine lists a model when it speaks one of its protocols (`copilotEntry`): Claude Code Messages, Codex Responses, the in-house engine and OpenCode all three, Messages first. The in-house engine calls Copilot in process; the other three are processes of their own that take an endpoint and a key, so the server runs a relay on loopback (`copilot-relay.ts`, started on first use, one random key per server process) that passes `/<account>/<path>` on through the same fetch. It also keeps each streamed Responses item on its first id: Copilot re-encrypts the id on every event, and OpenCode's SDK pieces items together by id. A turn still running when the server restarts has the old key and fails on its next request.

Remote access borrows one GitHub account (`remoteAccountId`), never signs in itself, and stops when that account signs out. Quota reads the same stores and never refreshes or persists Claude credentials; Codex and GitHub tokens are refreshed by their single owners per home or per account. Public snapshots carry identity, plan, uses and quota only.

## Passive usage and bounded fallback

`bindUsage` captures the account identity at turn start. Claude's pinned bridge forwards a whitelisted `rate_limit_event` through the harness's `raw` stream; the server consumes it rather than writing it into chat. Native Codex handles `account/rateLimits/updated` before filtering thread-scoped events. The in-house Codex provider observes quota headers on its existing requests. Missing fields do not mean zero; sparse updates merge windows and retain each window's observation time. OpenCode currently uses fallback only.

`usage-cache.ts` owns `<dataDir>/account-usage.json`: identity-keyed results and next-query reservations, plus provider-wide 429 cooldowns. It stores no credentials. A serialized atomic write reserves a 15-minute interval before credential access or a network request. Recent conversation data suppresses fallback. A 429 pauses the whole platform for at least 30 minutes, doubling on repeated failures to six hours, or longer if `Retry-After` says so. Passive updates never cancel this cooldown. Corrupt/unwritable state fails closed. Identity invalidation and server restart do not reset the request budget.

Web polls the local snapshot every minute; only a visible quota panel/settings page or an explicit refresh requests fallback, which remains subject to the same server budget. Failed reads retain prior data with a notice. The frontend never controls the actual upstream frequency.
