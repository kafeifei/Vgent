# Vgent 产品逻辑

> 2026-09-18 第一版；同日 M1–M5 落地后更新了「现状对照」和「工作计划」；2026-10-01 按代码补记停止也管还没开跑的回合、带回 / 撤销带回 / 提交 / 还原 / 丢弃的安全网、远程会话的边界、外部图片点了才加载、「一直允许」在设置里逐条移除。这份文档管「做什么、为什么、每个东西的一生」；`docs/architecture.md` 管「怎么实现」。
> 规矩：任何功能动手前，先在这里找到它落在任务生命周期的哪一步。落不上的不做。

## 一句话

Vgent 是本地的 agent 工作台：你派活，它干，你验收，收口。不是聊天软件，也不是 IDE。

## 理念（读 Cursor 3 文档得来，一手资料见文末）

Cursor 3 的 Agents Window 把人从「写代码」抬到「派活和验收」。它的单位不是一段聊天，是一个有目标的 agent，这个 agent 有完整的一生。所有界面元素都在服务这条线，并且尽量不打断人：

- 审批是**全局运行模式**加 allowlist，不是每个任务一个下拉。
- worktree 让多个 agent 互不干扰，并且有 setup 脚本，隔离目录里真能装依赖、跑测试。
- 验收在独立的 diffs 视图里做，验收完就地提交、开 PR 或带回主目录。
- 用户只选**模型**，不选「引擎」。
- Plan 是一条完整的线：澄清、调研、出计划、人改计划、点 Build。做歪了就回到计划重来，而不是追着修。

我们照搬的是这条线和这些取舍，不是它的功能清单。它的云产品线（cloud agents、Projects 协调者、订阅自动化、手机端）不在 Vgent 范围内。

## 首次启动与首次使用引擎

落在第 1 步「派活」的准备阶段：桌面安装包只带原生壳和初始化页。首次启动自动安装工作台运行环境，显示下载进度、校验和安装状态；失败保留窗口并提供重试，不影响任务数据。安装后离线启动复用缓存。Codex 在首次使用或缺少本机 CLI 的账号登录时另行安装，也可在设置里提前安装、查看进度和重试；Claude Code / OpenCode 继续按官方 harness 的首次使用流程安装。初始化页的联网需求只针对尚未安装的运行环境。

## 任务的一生

代码里任务叫 thread。一个任务 = 一个目标 + 一个运行位置 + 一个模型。

| 步 | 发生什么 | 用户看到什么 |
| --- | --- | --- |
| 1 派活 | 写目标，选项目、在哪跑、模型，可选 Plan | 空状态的聊天框和三个选择器 |
| 2 计划（可选） | agent 只读调研、提问、出计划；人可改 | 右栏「计划」文档 + Build 按钮 |
| 3 执行 | 自主干活；需要时等审批、等回答 | 工作日志；侧栏显示当前动作 |
| 4 纠偏 | 运行中人可以排队下一条，或停下改方向 | 聊天框下方的排队条 |
| 5 验收 | 看这个任务相对**任务基线**的全部改动 | 「审查 +N −M」和 diffs 视图 |
| 6 收口 | 提交 / 开 PR / 带回主目录 / 丢弃 | diffs 视图底部的动作条 |
| 7 归档 | 任务收起来，worktree 回收，可恢复 | 侧栏「已归档」，默认折叠 |

归档或回收 worktree 时若有未提交改动，关闭操作菜单并弹出居中确认窗口，说明文件数、改动如何保存及被 Git 忽略文件的处理；底部提供「取消 / 确认归档（回收）」。确认后才执行，干净的 worktree 直接处理（2026-09-30）。

### 两个维度的状态

**运行态**（已有，`ThreadStatus`）：`idle` / `running` / `awaiting-approval` / `awaiting-input` / `interrupted` / `error`。

**收口态**（新增）：

- `outcome`：无 / `committed` / `pr`（带链接）/ `applied` / `discarded`。
- `archivedAt`：有值即已归档。

另有一个小标记 `unread`（未读）：回合跑完、出错、停在等审批或等回答时由 server 标上，你在前台点开这个任务时清掉；你自己按停止的不算。

侧栏按状态分组时用这两个维度合出五组：**进行中**（running）、**待处理**（等审批、等回答、失败、中断，以及跑完了但还没看过的）、**待验收**（idle 且有未收口的改动）、**已完成**（已收口，或本来就没改动）、**已归档**（默认折叠）。「待验收」是现在缺的一组，它正是人最该看的那一组。

## 对象

**项目**：一个 git 仓库的主检出。linked worktree 和 `<dataDir>/worktrees/*` 永远不是项目。记忆、skills、worktree setup 配置都按项目走。

**运行位置**：一个选择器，两个值。

- 「本机 · 主目录」：任务直接改你手上的文件。任务基线是**任务第一轮开跑前那一刻的工作目录**（第一个 checkpoint），不是 `HEAD`，所以你自己本来就没提交的改动不算任务的改动；还没跑过的任务没有改动。收口只有提交，而且只提交任务动过的文件（任务改了一个你之前就改过的文件时，提交按整个文件走，界面要明说）；不要的改动按文件还原。不给「全部丢弃」，因为分不清哪些是任务改的、哪些是你自己没提交的。
- 「本机 · worktree」：任务在 `<dataDir>/worktrees/<id>` 的独立检出里干活，分支 `vgent/<id8>`，从项目**已提交的 HEAD** 开出，不带你未提交的改动，选择器里要明说。创建后跑项目的 setup 脚本。收口有提交、开 PR、带回主目录、丢弃。

**改动**：任务相对**任务基线**的 diff。worktree 任务的基线是 `workspace.baseCommit`，所以任务内提交过的、没提交的、未跟踪的都算。主目录任务的基线是它的第一个 checkpoint，提交之后基线前移到提交后的那一刻。

**无项目**（2026-09-20）：项目选择器里的一项。任务不指向任何仓库，在它自己的临时目录里跑，任务删掉目录也删掉；用来问问题、做一次性的活。落在任务生命周期第 1 步（派活）：少一个必须先选仓库的前提。跟仓库有关的（分支、worktree、变更、收口）对这种任务不出现。

**产物的显示**（2026-09-21）：任务做出来的东西，是什么就显示成什么。落在第 5 步（验收）：画了一张图，验收就是看图，不是读它的源码。三处，做法照 Cursor 和 Codex 桌面版（读包所得，笔记在参考目录的 `findings-6-rich-content.md`）：

- 右栏「文件」按类型预览：图片就是图片；SVG 和 markdown 默认预览、可切源码，选择会记住；其它仍是代码。
- 回合结束后，回复下面列出这一轮做出来的、能预览的文件，点一下在右栏打开。图片一律算；文档只有回复里提到了才算。
- 回复里的 markdown：`![](本地路径)` 显示这个任务自己的文件，点开进右栏；指向外部主机的图（`![](https://…)`）不自动加载，先显示一个写着主机名的按钮，点了才请求——图片地址本身就能把模型读到的东西带出去（`![](https://x/?d=…)`），所以点之前不向任何人发请求，点过的同一张这次访问里不再问，`data:` / `blob:` 图照常显示；指向本地文件的链接也在右栏打开，不去浏览器；公式用 KaTeX（`$$…$$`、`\(…\)`、`\[…\]`，单个 `$` 不算）；代码块里的 SVG 直接显示成图，源码一键可看。

回复里的图不管来源都是一个样子：一张大小适中的图，周围什么都没有；点开在叠层里放大，仍然是图；角上一个「下载」，存到「下载」文件夹。

SVG 永远只通过 `<img>` 显示，不放进页面；不做清洗，下载下来的就是原样文件。

**引导与队列**（2026-09-29）：任务运行中，纯文字的回车或发送按钮默认发引导，⌘回车明确放入下一回合队列。带附件的消息（包括只有附件、没有文字）按回车或点发送都排队到下一回合，不转为引导；排队条显示附件数量和文件名，编辑正文不影响附件。服务端确认入队后才清草稿，失败时文字和附件原样保留，已入队的附件随任务持久化。引导先进入可见的待处理列表：运行时接收、真正送入当前回合是两个不同状态；等待期间可「打断并发送」，停止当前回合并把这条消息作为下一回合发出。队列可上移、下移，也可把一条转为引导。当前回合没有可用输入点时，引导留在列表里并在回合结束后作为下一轮发送。正常完成后清理已接收的引导。Codex 通过原生 app-server 的 `turn/steer` 送入当前回合，Claude Code 通过 harness 的 `experimental_steer`，自研引擎在两步之间拉取；运行中的工具仍可能先完成，接收不等于已处理。

| MCP / skills / 记忆 | ✗ 未接 | ✗ 未接 | ✓ | ✓ 设置页的 MCP、自研引擎的记忆（同一个目录）、自己的 skill |
| 引导（运行中发的消息进当前回合） | ✓ harness 的 `experimental_steer` | ✓ 原生 app-server 的 `turn/steer` | ✓ 两步之间从队列取 | ✓ harness 的 `experimental_steer`（只报「已接收」，没有「已送入」） |
：顶上那条就是标题栏，拖它移动窗口，双击缩放；两个侧栏和会话之间的缝可以拖，有最小宽度，双击那条缝恢复原宽。重命名任务在侧栏行的菜单里。

**模型**：用户唯一要选的「大脑」。引擎（Codex / Claude Code / Vgent）是模型的实现细节：模型选择器一行一个模型（带来源图标），同一个模型不管几个引擎能跑都只出现一次；悬停一行展开第二级——引擎、上下文、推理强度、速度——各自再展开取值（2026-09-20，层级是用户画的）。直接点一行就按现状选中它。任务有了对话之后不能换引擎：别的引擎才有的模型不列出来，引擎子菜单里其它引擎置灰。

运行中也可以修改同一引擎内的模型、推理强度、上下文和速度（2026-09-29，落在第 4 步纠偏）。选择立即保存，下一回合（包括自动发送的排队消息）生效；当前回合及发进当前回合的引导继续使用开跑时的配置。模型菜单在运行中说明生效时机。

速度属于模型选项（第 1 步派活、第 4 步纠偏）：标准始终可选，快速、超快等档位由当前模型目录提供；没有额外档位就不显示速度菜单。选择按模型记忆，切换模型不携带对方不支持的档位。界面和运行时使用相同来源的能力数据，不把被引擎忽略的请求当作已启用加速。

**模型提供商**：一个带来模型的账号。分两种，在设置页同一个地方管：**订阅**（Claude 订阅、ChatGPT · Codex 订阅）和**用 key 接的**。订阅不用 key，用厂商自己的命令行登录（`claude auth login` / `codex login`），Vgent 不保存也看不到那个登录，只报告它在不在、是哪个账号、什么套餐：登录了就在「已添加」里，没登录就在「添加」菜单最上面，点它告诉你该跑哪条命令、跑完回来重新检查。谁能用哪个订阅是定死的，界面上明说：Claude 订阅只有 Claude Code 能用（Anthropic 的条款把这个登录限定在 Claude Code 里，自研 agent 不拿它调模型）；Codex 订阅 Codex 和自研 agent 都能用。订阅带来哪些模型，问的是厂商不是我们：Codex 订阅的清单向 ChatGPT 的 Codex 后端现拉（目前 5 个；后端对清单外的型号明确回「ChatGPT 账号下不支持」，所以这就是全部），Claude 订阅是三个别名（sonnet / opus / haiku）加上提供商目录里 Anthropic 的全部模型、用完整 id。订阅带来的模型默认全开，在提供商页这个订阅的「模型」表里可以按 agent 关掉不想在选择器里看到的；关掉只是不再列出，已经在用它的任务照跑。下面说的是用 key 接的那种。**有哪些提供商不是我们写的清单**：是 models.dev 的公开目录（两百多家，每家写明用哪个 AI SDK 包接、地址是什么、有哪些模型），server 拉下来缓存；新厂商不用等我们发版。设置页「模型与提供商」只铺开已添加的；其余都收在一个「添加」菜单里：没登录的 Codex 订阅、Claude 订阅、GitHub（Copilot）账号，然后「自定义」（公司网关、自己搭的服务），最后「更多 N 个提供商 >」展开整个目录、带搜索。连接只要填一把 key（地址因账号而异的几家，比如 Azure，才要填地址）；能向厂商要模型清单的，连接时顺带验一下 key。连上之后点这一家的「模型」——一张表，一行一个模型、一列一个 agent、一个开关——决定**每个 agent 用它的哪些模型**，这就是那张手动配置表，没有第二张；开关点了就存。（设置里原来另有一个「模型」页把所有家的表摞在一起，2026-09-20 删掉：提供商页已经全有。）表里的模型是目录里的加上向厂商现拉的，还能手动加一个 id。打开的模型出现在模型选择器里对应 agent 那组的下面，挂在提供商名字的小标题下；任务的 `model` 记成 `<提供商 id>:<模型 id>`。key 只存在本机、只进不出：任何接口和界面都不会再把它显示出来。Codex 只说 OpenAI 的 Responses 协议，所以它能接的是说这个协议的提供商：目录里用 `@ai-sdk/openai` 包接的那几家（OpenAI 自己等），和用户在「自定义」里点了「Codex 也用它」的服务；只有聊天补全接口的提供商 Codex 用不了，那一列就不出现。目录里有十几家要第三方适配包或云账号凭据的，接不了，菜单里不列。

模型表每个引擎列的表头有可见的「全选」滑块，订阅账号和 API 提供商共用：全部开启时滑块亮起，部分开启时点击补齐全选，再点关闭全部。搜索后只操作匹配且该引擎可用的模型（包含未展开显示的匹配项），没有可操作模型时禁用；不影响其他引擎或搜索范围外的选择。

**账号**（2026-09-29，用户审过并实现；上面「模型提供商」里订阅怎么登录、摆在哪的说法以这里为准）：一条登录，加上它开了哪些用途。三家：Claude、Codex、GitHub，同一家可以登录多个。落在任务生命周期第 1 步（派活：选模型时选的就是这一轮算谁的额度）和第 3 步（执行：没登录、登录失效、额度用完时就地处理）。

- 账号页：设置里「通用」下面新增「账号」，样子照 macOS 的互联网账户。一行一个账号：头像、邮箱或用户名、套餐；右上角「添加」选 Claude / Codex / GitHub。点开一个账号是它的详情：额度、用途开关、退出登录。
- 用途：每个账号一个「模型」开关，管这个号的模型出不出现在选择器里；用哪个引擎跑是模型的事，账号里不出现引擎选项（2026-09-29 用户纠正：build 196 按引擎给了「Codex 引擎的模型」「Vgent 引擎的模型」两个开关，不对）。GitHub 另有「远程访问」。Claude 订阅仍然只给 Claude Code，条款所限，不变。远程访问同一时间只挂一个 GitHub 账号，在 B 上打开会关掉 A，因为设备要在新账号下重新登记，打开前确认。开 PR 这次不算 GitHub 账号的用途，维持现状（有 `gh` 用 `gh`，没有就推分支、开 compare 页）。
- 本机原有的登录：终端里已经登录的 claude / codex 自动算这一家的第一个账号，不用重新登录；在 Vgent 里退出它，终端里也跟着退出，退出前确认。之后加的账号各用 Vgent 自己的目录（`<dataDir>/accounts/<id>`），终端里的 CLI 看不到它们。Claude 的额外账号只把登录分开（Claude Code 换了配置目录，钥匙串里就是另一条凭据），`~/.claude` 里的设置、CLAUDE.md、skills、插件、会话记录用软链接共用，否则换个号跑就像换了一台电脑。Codex 的额外账号只提供登录，运行时照旧用 Vgent 自己隔离的 Codex home。
- 登录全在 app 里完成，不让人去终端敲命令：Claude 跑 `claude auth login` 拿授权链接（已有）；Codex 改成 app 里拉起 `codex login` 打开浏览器（现在是让你去终端敲）；GitHub 用设备验证码（已有）。加第二个同家账号时浏览器里可能还登着第一个，这一步由用户在浏览器里切。同一个账号登录两次认得出来，不会多一行；恢复本机登录和重新登录也查重。任务报错和额度卡里的重新登录始终回到任务原来的账号，即使失效的登录已不在列表中，也不改成添加新账号。
- 模型选择器：一个账号就是一个来源。模型列表里的小标题就是账号，写出订阅的用户：「Claude · alice@example.com」「Codex · bob@example.com」「GitHub Copilot · @carol」。两个 Claude 号都开着，同一个模型在两个小标题下各出现一次，点哪一行就走哪个号。任务记下用的是哪个号（模型 id 前面加 `@<账号>:`，每家的第一个账号——本机登录、第一个 GitHub 号——不加）；以前的任务没记，算本机登录那个号。已有对话的任务可以换到同一引擎下另一个号的同一个模型接着跑：Codex 和自研引擎每轮现取凭据，直接可行；Claude Code 靠共用的会话记录（实测过：在另一个配置目录里开的会话，回到默认目录能 `--resume` 接上）；OpenAI 的加密推理内容跨号能不能用还没验过。
- 提供商页：开了模型用途的账号在「模型与提供商」里各占一行，模型表还在那里管；「管理」进账号页。「添加」菜单里的订阅项改成「添加 Claude 账号」「添加 Codex 账号」「添加 GitHub 账号」，走同一套登录。关掉一个账号的模型用途，它就从提供商页和选择器里消失。用 key 的提供商不变。
- 引导：需要账号的地方缺账号，就地弹同一个登录窗口，不跳去设置页。四处：模型选择器里一个能用的模型都没有；任务报未登录或登录失效；远程访问页没有 GitHub 账号（有多个时就地选用哪个）；额度卡说要重新登录。额度用完不自动换号：额度卡和报错卡里给「换到 <另一个号> 继续」，只在同一引擎下还有别的号开着时出现。
- 左下角账号面板列出全部账号和各自的额度，「管理」进账号页；聊天框下方的额度卡显示当前任务那个号的额度。
- 存储：设置里只存账号表（id、类型、目录、用途开关、顺序），不存任何 token。token 留在原来的主人那里：Claude 在钥匙串（额外账号是带目录哈希后缀的另一条），Codex 在各自目录的 `auth.json` 或钥匙串，GitHub 在 Vgent 自己的钥匙串条目里，一个账号一条。现有的模型隐藏清单和提供商排序迁到每家第一个账号名下。

**运行模式**：全局设置，三档，一一对应 harness 的权限模式：询问（allow-reads）/ 自动改文件（allow-edits）/ 全自动（allow-all）。外加一份全局 allowlist。审批卡上的「一直允许」写进 allowlist，不再是任务私有；名单在「设置 → 通用 → 一直允许」里看得到、撤得掉：有条目时这一组才出现，一行一条，右边一个 × 移除，新条目只来自审批卡。因为是全局的，粒度必须细：条目要么是一个工具名，要么是 `bash(<命令>)`：普通命令记命令头（`bash(ls)`），git、gh、docker、kubectl、npm / npx / pnpm / yarn / bun / bunx、cargo、go、pip、brew、make 这类记「命令头 + 紧跟的子命令」（`bash(git status)`，只有两词形式，`docker compose up` 记成 `bash(docker compose)`）。一条 shell 命令的每一段都在名单或内置安全清单里才免审。内置安全清单只放只读的：`ls`、`cat`、`pwd`、`rg`、`grep`、`find`、`git status`、`git diff`、`git log`、`node --version`；`pnpm test` 这类测试命令不在里面（它跑的是 agent 刚写的代码，第一次要问，点「一直允许」才进名单），清单里的命令带了会写文件或执行程序的选项（git 的 `--output`、`--ext-diff`，rg 的 `--pre`、`-z`，find 的 `-exec`、`-delete` 等）也照样要问。解析不了的、命令头后面先出现旗标的（`git -C x status`）、带 `sudo` 这类包装的，不给「一直允许」，永远询问。以前留下的 `bash(git)` 不再放行任何命令，名单里照列，可以移除。自研引擎另有两道守卫：任何模式下都不改 `.git` 里的东西；「自动改文件」下写 `.vgent/worktrees.json`、`.cursor/worktrees.json`（worktree 的 setup 脚本，以后会无人看管地跑）也要问。文件名按 macOS 的同名规则比（大小写、Unicode 写法），经符号链接写到 setup 配置抓不到；Claude Code、Codex、OpenCode 的原生写入工具不经过这两道守卫。默认运行模式是「询问」，原因见现状对照第 3 步。任务头和空状态不再有权限下拉。

**远程访问**：落在第 3、4 步，是同一批任务的第二个入口：另一台设备经 GitHub 登录和 Dev Tunnels 进来，派活、聊天、停止、审批、看文件、收口，任务仍在这台电脑上跑（用法和实现见 [remote-control.md](./remote-control.md)）。这台电脑被允许怎么做事只能在主机上改：运行模式和「一直允许」名单、MCP 服务器、电脑操作、引擎选项、提供商 / 订阅 / 引擎运行时的改动、账号的登录退出和用途、远程访问本身，远程会话都改不了，得到 403「此操作需在主机上完成」；设置里它只能改默认引擎、默认模型、默认运行位置、主题和密度（每个模型记住的选项和提供商排序也能写）。理由是一次被劫持的远程会话不该能把这台电脑留在「全自动」，或让它启动自己选的程序。远程读到的设置里 MCP 服务器只剩名字、连接方式、命令、环境变量名和剪到主机的地址，认不出来的参数一律打码。远程通过任务预览、下载文件或看 diff 时，Vgent 的数据目录（任务自己的 worktree、临时目录、附件、输出除外）、引擎运行时目录、Codex 的登录目录、Claude 和 OpenCode 的登录凭据都打不开，这些目录也不能从远程加成项目；没堵上的是：项目包着这些目录时远程还看得到文件名，也能让 agent 去读（这归运行模式管）。真实隧道上还没人验过这些限制。

**计划**：Plan 模式的产物，一份属于任务的 markdown，存 `<dataDir>/plans/<threadId>.md`，人可以直接改，Build 时原样交给 Agent 模式。

**M5 纠偏** — 已完成，2026-09-18 落 main，验收标准实测通过

- 运行中 Enter = 排队，回合结束自动发出，可删可改；草稿任何情况下不丢（按任务存在本地，切任务、刷新都在）。
  - 队列存在 server 上、属于任务，关掉窗口也照样往下发。
  - 只有回合正常结束（回到空闲）才自动发下一条。停在等审批 / 等回答时不发，否则会顶掉那次审批；被你手动停止或出错时队列原地暂停，由你决定继续发、改还是删。
  - 聊天框上方的排队条叫「排队」；右栏原来叫「队列」的 tab 其实是待审批和待回答，改名「待处理」。
- checkpoint：每个由用户消息开始的回合，开跑前给工作目录打快照（git 对象，不碰你的暂存区和 HEAD）。快照仍是任务基线和「上一轮」范围的依据；日志里的「恢复到此处」已于 2026-09-20 撤掉（用户：要的是分叉不是恢复），旧版本留在恢复点上的任务仍能「回到最新」。
- 分叉（2026-09-20）：每条回复下面那排小图标里（复制旁边，位置照 Cursor）有一个「分叉」，点了就开一个新任务——带着到这条回复为止的对话，输入框是空的，接着说你想说的；原任务原样不动。只分叉对话，不分叉文件：新任务在项目主目录跑，磁盘是什么样就是什么样。Claude Code / Codex 的会话自己记历史、新任务里没有，所以分叉后的第一轮把之前的对话以文字形式随消息带过去一次（只含文字、不含工具调用，超长留尾部）；自研引擎直接拿到复制的消息。
  - 只管 git 看得见的文件；被忽略的（node_modules、构建产物）不动。不是 git 仓库的项目没有 checkpoint。
  - 恢复前先给当前状态再打一个快照，所以恢复可以撤销。2026-09-19 起恢复只回退任务各轮动过的文件（每轮结束时多打一个快照来知道这一点），你自己改的其它文件不动；撤销是常驻的「回到最新」，不再是几秒钟的提示。
- 验收标准：运行中排两条，依次执行；恢复到第一条之前，文件回到当时状态。

### Claude 手动压缩反馈（2026-09-29）

服务于执行与纠偏：原生 `/compact` 发出后显示「正在压缩上下文…」，正常结束才显示「上下文已压缩」；失败、中断或未确认结果如实展示。压缩命令本身是一行状态，不画成用户消息，也不要求模型返回正文。原始对话保留；引擎尚未报告新的用量时，上下文环显示「待更新」，下一次模型调用后恢复。聊天样式页包含进行中、完成、失败和中断场景。

### 意外退出后的自动继续

服务于第 3 步执行和第 4 步纠偏：服务或桌面进程意外退出后，重新打开时自动继续退出前仍在执行的任务，不必逐个发送「继续」。保留原目标、历史、模型和运行模式；恢复准备期间可以停止，恢复失败显示原因并保留记录。不自动继续手动停止、已完成、已归档或等用户审批/回答的任务；原生引擎无法恢复的等待仍需用户处理。结果未落盘不等于操作未执行：续跑前要求核实文件、Git、进程及外部操作状态，不直接重放旧工具调用。

### 桌面升级保留系统授权（2026-09-29）

服务于第 3 步执行：升级桌面包不应让用户为同一项 macOS 权限反复授权。桌面构建使用固定 bundle ID 和 Developer ID 签名；替换时仍在运行的旧包保留 `Vgent.app` 名称，退出由用户决定。从历史临时签名迁移到正式签名时，可能需要重新授权一次。

### 引擎运行时连续升级（2026-10-01）

服务于第 3 步执行：升级不要求用户先用中间版本跑一轮任务。当前版还没跑过也可以继续手动或自动升级，保留原来的回退版本；本次安装失败或被打断时恢复安装前的当前版，不消耗那份回退备份。新版成功运行后再释放备份。设置页只显示当前版、可用更新和回退操作，不再显示「待验证」；页面可见时自动刷新本机状态，任务结束或后台更新完成后不必重开设置页。

### 2026-09-25 引擎可靠性

执行与纠偏现在保留每轮停止原因、任务续接状态和稳定输入 ID；自研预算耗尽或没有完整结束时不会标为正常响应。文件修改、子代理报告、记忆来源、规则作用域和自动压缩的契约及限制见 [engine-reliability.md](./engine-reliability.md)。此次没有界面改动；正常响应仍不等于用户目标已验收。

### 自研引擎缓存复用

服务于第 3 步执行和第 4 步纠偏：长任务不应因为计划更新而反复失去可复用的请求前缀。沿用 Codex / OpenCode 的会话缓存标识，通过 AI SDK 传参数；支持的 Responses 链路将动态状态追加到历史末尾，保留恢复和最新用户纠正语义。不新增缓存服务、诊断界面或压缩算法，不改原生引擎和登录流程。命中率以提供商逐请求用量为准，不承诺固定比例；规则或工具变化、历史压缩及后端缓存失效仍可能降低命中。实现和真实冒烟入口见 [architecture.md](./architecture.md#自研引擎请求缓存)。

### 聊天样式验收

设置 → 外观 → 聊天样式（也可在命令面板搜索“聊天样式”）打开内置场景页，服务于执行、纠偏和验收阶段的 UI 调整。复用正式 ThreadView、Composer、WorkLog 和 RightPane，覆盖消息排版、流式过程、工具、审批、提问、排队、异常恢复、工作区、归档和详情面板。样例通过本地 Chat transport 和内存 API 运行，不创建真实任务、不调用模型、不执行命令、不修改项目文件。页面可以发送、停止、处理表单、浏览样例文件、切换场景和重置。

工作过程按正文和用户插话分段折叠；正常结束、失败或重启中断后，文字说明仍保持可见，不随工具过程收起。中断回合残留的工具部分输出标为「已中断」，保留查看入口和已有内容，不再显示运行中。聊天样式页包含「重启后的工作过程」场景。

主题和密度沿用应用外观设置，点击会应用到整个软件；预览宽度和右栏拖动只影响本页。关闭页面恢复原工作台，原任务保持运行。新增渲染状态时同步增加 `features/style-lab/fixtures.ts` 场景，避免预览页和正式聊天脱节。

工具详情默认按字段、短列表、记录表格和可折叠层级展示；命令与日志保留等宽排版，计划复用步骤列表，MCP 文本与图片按内容类型呈现。每段输入、输出可切换原始数据并复制完整内容，长文本和集合分批展开。做法参考 OpenCode 的工具专用渲染与 [AI Elements Tool](https://elements.ai-sdk.dev/components/tool) 的可组合结果。聊天样式页补充结构化结果、嵌套长结果和 MCP 错误场景。

表格和 Mermaid 的操作在鼠标悬停或键盘聚焦时出现，触屏保持可见；Mermaid 使用应用主题色和单层边框，缩放操作横排，切换主题时重新绘制。

子代理详情显示本次实际使用的模型和可展开的思考内容；过程与结果左对齐，不使用缩进竖线。模型元数据从开始执行即随子代理消息返回并保存，旧记录缺失时显示“未记录”。支持 OpenAI Responses 思考摘要的子代理请求可展示摘要，保留原有思考强度和摘要关闭选项。聊天样式页包含运行中、已完成和历史缺失三种场景。

### 账号用量概览（2026-09-29）

服务于派活和执行：快速确认三家账号的可用状态与额度，不把账号管理资料常驻铺开。左下角以部分重叠的 GitHub / Codex / Claude 三家品牌图标和「账号用量」作为入口，未登录或加载失败时图标也保留，版本和连接状态不变；弹层默认每家一行，GitHub 只显示高级请求，Codex / Claude 显示主要周期额度，百分比统一为已用。默认无进度条、邮箱、套餐和重置时间，接近用尽才强调，用尽显示重置倒计时。

点击已登录账号原位展开该家详情，其他家的详情收起；完整额度、余额、身份、套餐、管理、更新时间和适用范围均在详情内，精确重置日期收进悬停提示。未登录仍保留行，点击交给账号登录入口；需重新登录同理，不展开额度。登录状态未知和用量读取失败分别显示，不伪装成未登录或 0%；刷新失败时保留上次结果并明示。此次只调整展示层并复用现有账号操作回调，不实现或改动登录流程；直接登录接线由独立登录任务负责。输入框旁独立用量卡片不变。

额度更新优先使用正常对话附带的数据（2026-09-30）：Claude Code 的额度事件、Codex 原生通知，以及自研引擎 Codex 响应头。账号用量面板或账号设置可见时，缺失或超过 15 分钟的数据才允许补查；手动刷新不绕过同一账号至少 15 分钟的请求间隔。面板关闭时只读取本机缓存，不向平台轮询额度。429 后暂停同平台的补查，至少 30 分钟，重复限流延长到最多 6 小时；平台 `Retry-After` 更长时以它为准，冷却期间对话仍可更新额度。结果、查询间隔和冷却落盘，换窗口、改用途和重启都不清零。缺失窗口不补零，增量信息保留其它窗口的原始更新时间。OpenCode 暂无可透传的账号额度事件，使用同一受限补查。

### 上下文用量口径修正（2026-09-30）

服务于第 3 步执行和第 4 步纠偏：聊天框下方的上下文圈按最近一次模型调用的完整输入计算，包含缓存读取和写入；缓存命中不表示上下文变小。累计输入、缓存命中率及折合 API 价使用同一组完整计数，费用分开计算未缓存输入、缓存读取和写入，思考不重复计入输出。OpenCode 旧版本漏算缓存的历史记录在读取时自动修正，重复打开和续聊不会重复相加。
