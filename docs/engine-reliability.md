# Vgent 引擎执行契约

2026-09-25。范围是 `@vgent/engine`、`@vgent/tools` 和 server 的调度、转录、恢复；没有改变界面，也没有替换 AI SDK 的循环。Codex / Claude Code 的内部执行仍由各自 runtime 负责，共享调度层不能替它们证明完成。

## 文件与命令

- `edit` / `write` 按规范化路径在同一 server 进程中串行执行读取、检查、修改。父子代理使用同一协调器，不同文件互不阻塞。全文件覆盖需要本工具集读过当前版本；过期读取或并发冲突会报错，要求重新读取。
- 这不是操作系统文件锁：外部编辑器、其他进程和 shell 写入不参与协调。工具写前复核内容，不能保证消除复核之后的外部竞态。
- 文件工具允许任务目录和明确配置的项目主检出；Skill 和保存的输出目录只额外授予读取。允许根和目标都做路径规范化。host shell 的范围由审批和指令约束，不是文件工具的路径沙箱。
- `read` 返回带行号的内容、原文件字节数和末尾换行标志。逐字节交付应用复制和字节比较验证，不能把显示文本相同当作字节相同。
- 本地命令提供有界的头尾预览和运行中更新，完整 stdout/stderr 保存到任务输出目录。输出文件可按行续读，包括大于 1 MiB 的命令日志；普通源码读取仍保留 1 MiB 限制。
- 开始工具及文件变更前检查取消信号；shell 取消传递到该命令自己的进程组。已经提交的文件写入和远端副作用不能倒退。恢复时核实未结操作，不能盲目重放。

## 任务、回合与输入

- `updatePlan` 可保存目标、约束、已有授权、待办、完成证据和下一步。省略旧的未完成项不会隐式删除它，替换需要明确说明原因。简单问答不强制创建计划。
- 当前会话的明确要求优先于旧记忆和项目默认值；已授权的必要交付继续执行。固定提示不再要求每次提交重新授权，也不再一律禁止安装依赖。
- 每轮在用户消息的 `metadata.run` 保存运行 ID、引擎、模型、起止时间、最后事件、停止原因、步骤数和可获得的 provider 尝试次数。返回文本表示正常响应，不表示任意自然语言任务都已完成。
- 自研循环预留最后一步做交接，禁止该步启动新工具操作。预算耗尽、空回复和不完整结束为 `interrupted`；错误、用户停止、等待审批/输入分别记录。历史缺失和进程恢复后的未知状态保持未知，不倒推原因。
- 自研插话使用稳定 ID，写入转录和消费队列同一次持久化提交。普通队列消息先领取，开跑落盘后才消费；领取后崩溃会恢复为待处理。旧转录/队列写入不能重新插入已消费的 ID。对远端模型是否已接收的未知状态，不承诺恰好一次执行。

## 规则、记忆与子代理

- 全局 `~/.agents/AGENTS.md` 和仓库的 `AGENTS.md` 在每轮加载；项目规则入库，worktree 自带。访问过的子目录规则在下一步重新读取，附带路径作用域，兄弟目录规则互不扩张。模型仍须在修改前读取相关文件和规则。
- 子代理继承项目指令、权限和允许根；父任务的计划跟在交给它的任务消息里。读到子目录时，该目录的规则随读取结果返回。其结果包含任务 ID、完成/未完成/失败/取消、停止原因、摘要、完整报告和转录引用；`resume_task_id` 可以继续同类型子任务。
- 子代理长报告尝试做有界摘要；摘要失败明确标记未完成并保留详情。没有最终报告不视为完成。子任务返回 `completed` 仅说明正常交回报告，父代理还要核对目标和证据。
- 新记忆分用户约定、事实和推断。用户约定必须逐字引用用户在本任务里说过的话，工具在用户消息里找到这句并记下消息 ID，正文保存原话；推断不构成授权。修改保存来源、项目作用域、前版哈希和历史备份。历史插话在下轮也可作为来源；当前轮刚插入的话要到下一轮才查得到。

## 上下文与 provider

- 输入预算包括指令、工具定义、历史及输出预留，使用已知模型容量，并由实际 usage 向上校准估算。优先裁剪旧 reasoning/工具内容，仍放不下时摘要较早历史，保留近期用户边界后的原文。
- 摘要保留目标、授权、约束、未完成交付和证据。每个摘要请求也受容量限制，最多 32 个分块加一次归并；摘要失败、单条最新输入过大或规则本身过大时明确终止，保留原历史，不无限重发。
- 原始对话仍在 server 转录；自动摘要详情另有文件。压缩缓存只复用哈希完全一致的历史前缀，编辑、分叉或不兼容历史会放弃缓存。手动压缩保留近期原文和原有压缩前快照。
- 错误分类包括授权、模型不可用、限流、上游错误、上下文容量、连接、超时和取消。403/模型不可用/超限即使被网关标成可重试，也终止重试；瞬时失败复用 SDK 有界重试，流启动后的不确定副作用不自动重放。已有空回复重试和 reasoning 提取继续使用。

## 持久化位置与验证

任务计划在 thread record；回合诊断在 user message metadata。`<dataDir>/outputs/<threadId>/` 保存命令输出、上下文归档、压缩缓存和 `child-<taskId>.json` / 报告。项目记忆的前版在 `<memoryDir>/.history/`。原始记录可能包含用户文件内容，默认私有文件权限；本次不自动清理用户历史或输出。

确定性回归在 `mutations.test.ts`、`reliability.test.ts`、`subagents.test.ts`、`queue-durability.test.ts`、`engine-reliability.test.ts`，并运行现有三个引擎的共享 server 套件。包括真实生产 factory 的 100 步停止、文件竞态、队列崩溃窗口、作用域实际请求、记忆原话、压缩预算和子代理恢复。

`packages/engine/scripts/engine-eval.mts` 是显式启用的真实模型回归，默认 10 个隔离任务、每个 3 次，每例最多 8 步、90 秒、12 次模型尝试，每快照最多 240 次尝试。需要 `VGENT_LIVE_EVAL=1`、`VGENT_EVAL_OUTPUT`，可指定模型、版本和场景；使用测试的源码 alias tsconfig 执行。原 session 仅作场景依据，不重放其中命令。结果中的 `pass` 只代表文件断言；报告必须同时检查最终文本、错误、停止原因及工具证据，不得据此宣称通用任务胜率或与 Codex 引擎等价。
