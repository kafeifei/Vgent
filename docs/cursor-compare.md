# 对照 Cursor 3.19.7：任务一生的每一步

> 2026-09-19。这是给 `docs/product.md` 用的第二份一手资料：第一份是 Cursor 的官方文档，这一份是真装在本机的 Cursor 3.19.7。
> 来源：Agents Window 的一张窗口截图（只截它自己的窗口），加上对它随包发布的 Agents Window 前端代码的只读阅读（五份笔记，约 15 万字符，不进仓库）。
> 只取行为、状态、默认值和界面文案，不取代码。
> 标注：【见】= 在代码或截图里直接看到；【推】= 从看到的逻辑推断；【未定】= 没能确定。
> **这份文档只是对照和建议。在用户拍板之前，界面和逻辑都不按它改。**

## 结论

### 建议改（按性价比排）

| # | 改什么 | 落在哪一步 | 为什么 | 量 |
| --- | --- | --- | --- | --- |
| 1 | 模型选择器去掉引擎分组，平铺成一份模型清单 | 1 派活 | Cursor 根本没有「引擎」这根轴，用户能选的只有模型和「在哪跑」。我们现在同一个 GPT-5.5 出现两次，用户得懂引擎才会选 | 中 |
| 2 | 系统通知 + 未读 | 3 执行 → 5 验收 | 派完活人会切走。现在任务跑完或卡在审批，没有任何东西叫你回来，这条线断在「回来验收」 | 中 |

### 保持我们的做法（和 Cursor 不同，但我们的更对）

- **提交只提交任务动过的文件，由 server 直接跑 git。** Cursor 的按钮是给 agent 发一条隐藏消息让它去提交，没勾选时提交工作目录里的全部改动【见】。我们的做法确定、不花 token、不会把你自己的改动带进去。
- **回收 worktree 前先快照。** Cursor 超限清理是硬删，只保护 10 分钟内新建的和正在跑的，不看里面有没有还没收口的改动【见，最后一点推·强】。
- **「待验收」分组。** Cursor 没有这个状态，它用「未读」顶替：跑完没看过的算 Needs Attention，点开看一眼就进 Done。我们的定义（空闲且有没收口的改动）更贴「验收—收口」这条线。未读作为补充加上，不替换。
- **停止或出错后队列暂停。** Cursor 不清队列【见】，之后是否自动接着发【未定】。我们明确由人决定。
- **等审批时新消息排队。** Cursor 在等审批且队列为空时直接发送，会顶掉那次审批【见】。
- **Plan 的只读在本地强制。** Cursor 客户端给 Plan 模式的工具和 Agent 一样，只读靠服务端约束【见/推】。
- **队列存在 server 上。** Cursor 存在对话文档里，由窗口派发【见】。我们关掉窗口也照样往下发。
- **worktree 一开始就有分支。** Cursor 默认建 detached 的 worktree，分支等要提交时才建【见】。我们收口更简单。

### 不做

Steer（回合中注入，三个引擎做法各不同）、Debug 和 Multitask 模式、对话中途迁移运行位置、选用已有的 worktree、多任务平铺、Find Issues 审查、staged 和 unstaged 以及按提交看改动、逐块 Keep/Undo、计划里的结构化 todo 和只构建选中项、在界面里合并 PR、语音、插件市场、沙箱和 Auto-review。云端和远程那一套本来就不在范围内。

可选、便宜、等用户一句话的：Ask 模式（只读问答，复用 Plan 的只读工具集）；Plan 回合结束时聊天框上方的 Build 提示条；文件列表里的「已看」勾；停止后把被停的那条放回输入框；在 main 上提交前问一句要不要先开分支；拒绝审批时附一句理由。

## 界面骨架（结论第 10 条，范围等用户定）

截图里看到的和我们现在的差别，只有这几处是结构性的：

1. **侧栏顶部**：Cursor 是四个朴素入口（New Chat、Search、Automations、Customize），任务嵌在项目文件夹下面，筛选和分组收在一个图标里。我们顶部堆了项目下拉、密度、主题、⌘K、新任务、分组下拉。
2. **聊天框**：Cursor 框内只有「+」、输入、模型、发送；分支、运行位置、上下文环在框**下方**常驻一行，框上方什么都没有。我们框内有四个 chip，框上方有位置标签和「审查」。
3. **右栏**：Cursor 是「On owner/repo」标题下的竖排入口（Changes、Browser、Terminal、Files），点开才成为 tab。我们是横排五个 tab。
4. **标题栏**：Cursor 有前进后退（任务导航历史）、标题、「…」菜单、面板开关。我们是标题、分支、收口徽标、右栏开关。
5. **回复下方的动作行**：Cursor 有复制、fork、时间。我们只有用户消息上的「恢复到此处」。
