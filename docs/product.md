# Vgent 产品逻辑

> 2026-09-18 第一版；同日 M1–M5 落地后更新了「现状对照」和「工作计划」。这份文档管「做什么、为什么、每个东西的一生」；`docs/architecture.md` 管「怎么实现」。
> 规矩：任何功能动手前，先在这里找到它落在任务生命周期的哪一步。落不上的不做。

## 一句话

Vgent 是本地的 agent 工作台：你派活，它干，你验收，收口。不是聊天软件，也不是 IDE。

## 理念（读 Cursor 3 文档得来，一手资料见文末）

Cursor 3 的 Agents Window 把人从「写代码」抬到「派活和验收」。它的单位不是一段聊天，是一个有目标的 agent，这个 agent 有完整的一生。所有界面元素都在服务这条线，并且尽量不打断人：

- 审批是**全局运行模式**加 allowlist，不是每个任务一个下拉。
- worktree 让多个 agent 互不干扰，并且有 setup 脚本，隔离目录里真能装依赖、跑测试。
- 验收在独立的 diffs 视图里做，验收完就地提交、开 PR 或带回主目录。
- 用户只选**模型**，不选「引擎」。
- Plan 是一条完整的线：澄清、调研、出计划、人改计划、点 Build。做歪了就回到计划重来，而不是追着修。

我们照搬的是这条线和这些取舍，不是它的功能清单。它的云产品线（cloud agents、Projects 协调者、订阅自动化、手机端）不在 Vgent 范围内。

## 任务的一生

代码里任务叫 thread。一个任务 = 一个目标 + 一个运行位置 + 一个模型。

| 步 | 发生什么 | 用户看到什么 |
| --- | --- | --- |
| 1 派活 | 写目标，选项目、在哪跑、模型，可选 Plan | 空状态的聊天框和三个选择器 |
| 2 计划（可选） | agent 只读调研、提问、出计划；人可改 | 右栏「计划」文档 + Build 按钮 |
| 3 执行 | 自主干活；需要时等审批、等回答 | 工作日志；侧栏显示当前动作 |
| 4 纠偏 | 运行中人可以排队下一条，或停下改方向 | 聊天框下方的排队条 |
| 5 验收 | 看这个任务相对**任务基线**的全部改动 | 「审查 +N −M」和 diffs 视图 |
| 6 收口 | 提交 / 开 PR / 带回主目录 / 丢弃 | diffs 视图底部的动作条 |
| 7 归档 | 任务收起来，worktree 回收，可恢复 | 侧栏「已归档」，默认折叠 |

### 两个维度的状态

**运行态**（已有，`ThreadStatus`）：`idle` / `running` / `awaiting-approval` / `awaiting-input` / `interrupted` / `error`。

**收口态**（新增）：

- `outcome`：无 / `committed` / `pr`（带链接）/ `applied` / `discarded`。
- `archivedAt`：有值即已归档。

另有一个小标记 `unread`（未读）：回合跑完、出错、停在等审批或等回答时由 server 标上，你在前台点开这个任务时清掉；你自己按停止的不算。

侧栏按状态分组时用这两个维度合出五组：**进行中**（running）、**待处理**（等审批、等回答、失败、中断，以及跑完了但还没看过的）、**待验收**（idle 且有未收口的改动）、**已完成**（已收口，或本来就没改动）、**已归档**（默认折叠）。「待验收」是现在缺的一组，它正是人最该看的那一组。

## 对象

**项目**：一个 git 仓库的主检出。linked worktree 和 `<dataDir>/worktrees/*` 永远不是项目。记忆、skills、worktree setup 配置都按项目走。

**运行位置**：一个选择器，两个值。

- 「本机 · 主目录」：任务直接改你手上的文件。任务基线是**任务第一轮开跑前那一刻的工作目录**（第一个 checkpoint），不是 `HEAD`，所以你自己本来就没提交的改动不算任务的改动；还没跑过的任务没有改动。收口只有提交，而且只提交任务动过的文件（任务改了一个你之前就改过的文件时，提交按整个文件走，界面要明说）；不要的改动按文件还原。不给「全部丢弃」，因为分不清哪些是任务改的、哪些是你自己没提交的。
- 「本机 · worktree」：任务在 `<dataDir>/worktrees/<id>` 的独立检出里干活，分支 `vgent/<id8>`，从项目**已提交的 HEAD** 开出，不带你未提交的改动，选择器里要明说。创建后跑项目的 setup 脚本。收口有提交、开 PR、带回主目录、丢弃。

**改动**：任务相对**任务基线**的 diff。worktree 任务的基线是 `workspace.baseCommit`，所以任务内提交过的、没提交的、未跟踪的都算。主目录任务的基线是它的第一个 checkpoint，提交之后基线前移到提交后的那一刻。

**无项目**（2026-09-20）：项目选择器里的一项。任务不指向任何仓库，在它自己的临时目录里跑，任务删掉目录也删掉；用来问问题、做一次性的活。落在任务生命周期第 1 步（派活）：少一个必须先选仓库的前提。跟仓库有关的（分支、worktree、变更、收口）对这种任务不出现。

**产物的显示**（2026-09-21）：任务做出来的东西，是什么就显示成什么。落在第 5 步（验收）：画了一张图，验收就是看图，不是读它的源码。三处，做法照 Cursor 和 Codex 桌面版（读包所得，笔记在参考目录的 `findings-6-rich-content.md`）：

- 右栏「文件」按类型预览：图片就是图片；SVG 和 markdown 默认预览、可切源码，选择会记住；其它仍是代码。
- 回合结束后，回复下面列出这一轮做出来的、能预览的文件，点一下在右栏打开。图片一律算；文档只有回复里提到了才算。
- 回复里的 markdown：`![](本地路径)` 显示这个任务自己的文件，点开进右栏；指向本地文件的链接也在右栏打开，不去浏览器；公式用 KaTeX（`$$…$$`、`\(…\)`、`\[…\]`，单个 `$` 不算）；代码块里的 SVG 直接显示成图，源码一键可看。

SVG 永远只通过 `<img>` 显示，不放进页面。

**模型**：用户唯一要选的「大脑」。引擎（Codex / Claude Code / Vgent）是模型的实现细节：模型选择器一行一个模型（带来源图标），同一个模型不管几个引擎能跑都只出现一次；悬停一行展开第二级——引擎、上下文、推理强度、Fast——各自再展开取值（2026-09-20，层级是用户画的）。直接点一行就按现状选中它。任务有了对话之后不能换引擎：别的引擎才有的模型不列出来，引擎子菜单里其它引擎置灰。

**模型提供商**：一个带来模型的账号。分两种，在设置页同一个地方管：**订阅**（Claude 订阅、ChatGPT · Codex 订阅）和**用 key 接的**。订阅不用 key，用厂商自己的命令行登录（`claude auth login` / `codex login`），Vgent 不保存也看不到那个登录，只报告它在不在、是哪个账号、什么套餐：登录了就排在「已连接」最上面，没登录就排在「热门」最上面，点「登录」告诉你该跑哪条命令、跑完回来重新检查。谁能用哪个订阅是定死的，界面上明说：Claude 订阅只有 Claude Code 能用（Anthropic 的条款把这个登录限定在 Claude Code 里，自研 agent 不拿它调模型）；Codex 订阅 Codex 和自研 agent 都能用。订阅带来哪些模型，问的是厂商不是我们：Codex 订阅的清单向 ChatGPT 的 Codex 后端现拉（目前 5 个；后端对清单外的型号明确回「ChatGPT 账号下不支持」，所以这就是全部），Claude 订阅是三个别名（sonnet / opus / haiku）加上提供商目录里 Anthropic 的全部模型、用完整 id。订阅带来的模型默认全开，在提供商页这个订阅的「模型」表里可以按 agent 关掉不想在选择器里看到的；关掉只是不再列出，已经在用它的任务照跑。下面说的是用 key 接的那种。**有哪些提供商不是我们写的清单**：是 models.dev 的公开目录（两百多家，每家写明用哪个 AI SDK 包接、地址是什么、有哪些模型），server 拉下来缓存；新厂商不用等我们发版。设置页「模型提供商」照 Koma 的样子：已连接的、几家热门的、「自定义」（公司网关、自己搭的服务）、「查看全部」带搜索。连接只要填一把 key（地址因账号而异的几家，比如 Azure，才要填地址）；能向厂商要模型清单的，连接时顺带验一下 key。连上之后点这一家的「模型」——一张表，一行一个模型、一列一个 agent、一个开关——决定**每个 agent 用它的哪些模型**，这就是那张手动配置表，没有第二张；开关点了就存。（设置里原来另有一个「模型」页把所有家的表摞在一起，2026-09-20 删掉：提供商页已经全有。）表里的模型是目录里的加上向厂商现拉的，还能手动加一个 id。打开的模型出现在模型选择器里对应 agent 那组的下面，挂在提供商名字的小标题下；任务的 `model` 记成 `<提供商 id>:<模型 id>`。key 只存在本机、只进不出：任何接口和界面都不会再把它显示出来。Codex 只说 OpenAI 的 Responses 协议，所以它能接的是说这个协议的提供商：目录里用 `@ai-sdk/openai` 包接的那几家（OpenAI 自己等），和用户在「自定义」里点了「Codex 也用它」的服务；只有聊天补全接口的提供商 Codex 用不了，那一列就不出现。目录里有十几家要第三方适配包或云账号凭据的，照样列出来、标明原因、不能点。

**运行模式**：全局设置，三档，一一对应 harness 的权限模式：询问（allow-reads）/ 自动改文件（allow-edits）/ 全自动（allow-all）。外加一份全局 allowlist。审批卡上的「一直允许」写进 allowlist，不再是任务私有。因为是全局的，粒度必须细：条目要么是一个工具名，要么是 `bash(<命令>)`：普通命令记命令头（`bash(ls)`），git、gh、docker、kubectl、npm / npx / pnpm / yarn / bun / bunx、cargo、go、pip、brew、make 这类记「命令头 + 紧跟的子命令」（`bash(git status)`，只有两词形式，`docker compose up` 记成 `bash(docker compose)`）。一条 shell 命令的每一段都在名单或内置安全清单里才免审；解析不了的、命令头后面先出现旗标的（`git -C x status`）、带 `sudo` 这类包装的，不给「一直允许」，永远询问。以前留下的 `bash(git)` 不再放行任何命令，设置页标「已失效」。默认运行模式是「询问」，原因见现状对照第 3 步。任务头和空状态不再有权限下拉。

**计划**：Plan 模式的产物，一份属于任务的 markdown，存 `<dataDir>/plans/<threadId>.md`，人可以直接改，Build 时原样交给 Agent 模式。

## 引擎能力表

界面显示什么由这张表决定，由 server 在 `GET /api/engines` 里下发；web 里不允许再写 `engine === "vgent"` 这种判断。

| 能力 | Claude Code | Codex | 自研 |
| --- | --- | --- | --- |
| 审批（能「询问」） | ✓ | ✗ 只能全自动 | ✓ |
| 提问 askUserQuestions | ✗ | ✗ | ✓ |
| 计划 / 待办 | ✓ TodoWrite | ✓ update_plan（目前不出 UI 部件） | ✓ updatePlan |
| Plan 模式 | ✓ 只读 + 提示词 | ✗（不能只读） | ✓ 只读工具 + 提示词 |
| 压缩上下文 | 引擎自管 | 引擎自管 | ✓ 手动 + 超预算裁剪 |
| 默认模型可知 | ✗ | ✗ | ✓ |
| MCP / skills / 记忆 | ✗ 未接 | ✗ 未接 | ✓ |
| 用订阅 | ✓ Claude 订阅 | ✓ Codex 订阅 | ✓ Codex 订阅（Claude 订阅不行，条款所限） |
| 接用 key 的提供商 | ✓ 说 Anthropic 协议的那些 | ✓ 说 OpenAI Responses 协议的那些 | ✓ AI SDK 官方包能接的全部（15 种接法）+ OpenAI / Anthropic 兼容 |

能力缺失的处理原则：**明说，不装**。例：运行模式是「询问」而选了 Codex 的模型，聊天框上方一行提示「Codex 不支持审批，这个任务会全自动运行」，而不是摆一个点不了的下拉。

| 2 计划 | Plan 回合强制只读，最后的回复存成任务的计划文档；「计划」tab 上方是文档（可编辑、可保存）+ Build，下方仍是待办（M4） | Codex 不支持（能力表里写明，chip 置灰说明原因）；恢复 checkpoint 不回滚计划文档 |
| 3 执行 | 三引擎、审批卡、提问卡、子代理、记忆；worktree 建好后跑项目的 setup 脚本（M2）；「一直允许」写进全局 allowlist，细到子命令（`git status` 和 `git push` 是两条，2026-09-19）；拒绝审批后回合自己结束（修了 harness 引擎上一直存在的卡死）；任务跑完、出错、等审批、等回答时标未读，窗口不在前台就发一条系统通知，设置页「系统通知」默认开（2026-09-19） | 「自动改文件」和「全自动」在 Claude Code 上不拦工作目录外的写入：harness 桥接层对编辑类工具一律放行、不看路径，worktree 任务可以不经询问改到你的主目录；自研引擎没有这个问题（写工具出不了工作目录）。所以默认运行模式留在「询问」；系统通知真的弹出来只有装好的桌面包里看得到，还没人验过；审批通知里「是什么工具」只有当前窗口加载过那个任务的对话时才填得出来 |
| 4 纠偏 | 停止；运行中回车 = 排队，队列在 server 上，回合正常结束自动发下一条，可改可删，暂停时可手动发（M5）；运行中队首那条可以「打断并发送」：先停当前这轮再发它（2026-09-19）；草稿、主题、密度存在 server 上，换端口、重启、换窗口都在，浏览器本地只当首帧缓存（2026-09-19）；发送要等 server 收下才清输入框，被拒时文字留在框里（2026-09-19）；每轮开跑前和结束时各打一个 checkpoint，用户消息上「恢复到此处」只回退从那条消息到当前位置各轮动过的文件，你自己改的其它文件不动（任务动过、你又手改过的会被覆盖，确认文案写明会动几个文件）；恢复不再是 8 秒的提示：恢复点之后的消息变灰，有常驻横幅「已恢复到这里，后面的改动已撤销 / 回到最新」，点灰掉的消息就前进到那里，消息永不删除；从恢复点发新消息会清掉标记，并告诉模型一次后面几轮的改动已撤销（2026-09-19） | 桌面 app 首帧可能闪一下默认深色；草稿这条线在真 WebView 里还没人验过（换端口在浏览器里验过） |
| 5 验收 | 「审查 +N −M」、diff、按文件还原，全部对任务基线算（M1）；变更面板顶部有「全部改动 / 上一轮」切换，「上一轮」是最后一轮前后两个快照的树对树比较，只看不改，至少两轮且最后一轮跑完才出现（2026-09-19） | 基线功能之前建的主目录任务仍对 `HEAD` 算，动作条上有一句说明；主目录任务的「审查 +N −M」会把你自己在任务开跑之后改的无关文件算进去（单一基线固有的），恢复之后看着尤其别扭；回合运行期间你自己改的文件会算到那一轮头上；有回合没记下结束状态时（老任务、崩过、快照过期）恢复退回整目录，确认文案会明说 |
| 6 收口 | 提交、开 PR、带回主目录、全部丢弃；收口结果显示在任务头、侧栏行和动作条（M1）；开 PR 不再需要 `gh`：没有它就推分支并打开 GitHub 的 compare 页，远端不是 GitHub 就只推分支并说明；PR 链接单独存，新一轮不再清掉（2026-09-19）；带回主目录改成逐文件三方合并，默认有冲突整体不动并逐个说明原因，可选「带冲突标记合并」，带回之后可以「撤销带回」，只还原你之后没再动过的文件（2026-09-19） | 任务改了你之前就改过、还没提交的文件时，提交按整个文件走，你那部分也会进去（动作条会写「其中 M 个含你之前未提交的改动，会一起提交」）；`gh` 那条路和真 GitHub 远端都没实跑过（只对着本地裸仓库验了推送和 compare 地址）；删改冲突、二进制和符号链接冲突不写标记，只跳过并列出来 |
| 7 归档 | 侧栏行菜单归档 / 取消归档 / 删除，归档顺带回收 worktree；「待验收」「已归档」分组（M1）；worktree 上限 25、自动回收最旧的（M2）；侧栏行有未读点，行菜单可「标为未读 / 标为已读」，按状态分组时跑完没看过的留在「待处理」（2026-09-19） | 上限还没有设置界面（M3 的设置页里做） |

**M5 纠偏** — 已完成，2026-09-18 落 main，验收标准实测通过

- 运行中 Enter = 排队，回合结束自动发出，可删可改；草稿任何情况下不丢（按任务存在本地，切任务、刷新都在）。
  - 队列存在 server 上、属于任务，关掉窗口也照样往下发。
  - 只有回合正常结束（回到空闲）才自动发下一条。停在等审批 / 等回答时不发，否则会顶掉那次审批；被你手动停止或出错时队列原地暂停，由你决定继续发、改还是删。
  - 聊天框上方的排队条叫「排队」；右栏原来叫「队列」的 tab 其实是待审批和待回答，改名「待处理」。
- checkpoint：每个由用户消息开始的回合，开跑前给工作目录打快照（git 对象，不碰你的暂存区和 HEAD）。快照仍是任务基线和「上一轮」范围的依据；日志里的「恢复到此处」已于 2026-09-20 撤掉（用户：要的是分叉不是恢复），旧版本留在恢复点上的任务仍能「回到最新」。
- 分叉（2026-09-20）：每条回复下面那排小图标里（复制旁边，位置照 Cursor）有一个「分叉」，点了就开一个新任务——带着到这条回复为止的对话，输入框是空的，接着说你想说的；原任务原样不动。只分叉对话，不分叉文件：新任务在项目主目录跑，磁盘是什么样就是什么样。Claude Code / Codex 的会话自己记历史、新任务里没有，所以分叉后的第一轮把之前的对话以文字形式随消息带过去一次（只含文字、不含工具调用，超长留尾部）；自研引擎直接拿到复制的消息。
  - 只管 git 看得见的文件；被忽略的（node_modules、构建产物）不动。不是 git 仓库的项目没有 checkpoint。
  - 恢复前先给当前状态再打一个快照，所以恢复可以撤销。2026-09-19 起恢复只回退任务各轮动过的文件（每轮结束时多打一个快照来知道这一点），你自己改的其它文件不动；撤销是常驻的「回到最新」，不再是几秒钟的提示。
- 验收标准：运行中排两条，依次执行；恢复到第一条之前，文件回到当时状态。
