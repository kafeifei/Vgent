# Vgent 产品逻辑

> 2026-09-18 第一版；同日 M1–M5 落地后更新了「现状对照」和「工作计划」。这份文档管「做什么、为什么、每个东西的一生」；`docs/architecture.md` 管「怎么实现」。
> 规矩：任何功能动手前，先在这里找到它落在任务生命周期的哪一步。落不上的不做。

## 一句话

Vgent 是本地的 agent 工作台：你派活，它干，你验收，收口。不是聊天软件，也不是 IDE。

## 理念（读 Cursor 3 文档得来，一手资料见文末）

Cursor 3 的 Agents Window 把人从「写代码」抬到「派活和验收」。它的单位不是一段聊天，是一个有目标的 agent，这个 agent 有完整的一生。所有界面元素都在服务这条线，并且尽量不打断人：

- 审批是**全局运行模式**加 allowlist，不是每个任务一个下拉。
- worktree 让多个 agent 互不干扰，并且有 setup 脚本，隔离目录里真能装依赖、跑测试。
- 验收在独立的 diffs 视图里做，验收完就地提交、开 PR 或带回主目录。
- 用户只选**模型**，不选「引擎」。
- Plan 是一条完整的线：澄清、调研、出计划、人改计划、点 Build。做歪了就回到计划重来，而不是追着修。

我们照搬的是这条线和这些取舍，不是它的功能清单。它的云产品线（cloud agents、Projects 协调者、订阅自动化、手机端）不在 Vgent 范围内。

## 任务的一生

代码里任务叫 thread。一个任务 = 一个目标 + 一个运行位置 + 一个模型。

| 步 | 发生什么 | 用户看到什么 |
| --- | --- | --- |
| 1 派活 | 写目标，选项目、在哪跑、模型，可选 Plan | 空状态的聊天框和三个选择器 |
| 2 计划（可选） | agent 只读调研、提问、出计划；人可改 | 右栏「计划」文档 + Build 按钮 |
| 3 执行 | 自主干活；需要时等审批、等回答 | 工作日志；侧栏显示当前动作 |
| 4 纠偏 | 运行中人可以排队下一条，或停下改方向 | 聊天框下方的排队条 |
| 5 验收 | 看这个任务相对**任务基线**的全部改动 | 「审查 +N −M」和 diffs 视图 |
| 6 收口 | 提交 / 开 PR / 带回主目录 / 丢弃 | diffs 视图底部的动作条 |
| 7 归档 | 任务收起来，worktree 回收，可恢复 | 侧栏「已归档」，默认折叠 |

### 两个维度的状态

**运行态**（已有，`ThreadStatus`）：`idle` / `running` / `awaiting-approval` / `awaiting-input` / `interrupted` / `error`。

**收口态**（新增）：

- `outcome`：无 / `committed` / `pr`（带链接）/ `applied` / `discarded`。
- `archivedAt`：有值即已归档。

侧栏按状态分组时用这两个维度合出五组：**进行中**（running）、**待处理**（等审批、等回答、失败、中断）、**待验收**（idle 且有未收口的改动）、**已完成**（已收口，或本来就没改动）、**已归档**（默认折叠）。「待验收」是现在缺的一组，它正是人最该看的那一组。

## 对象

**项目**：一个 git 仓库的主检出。linked worktree 和 `<dataDir>/worktrees/*` 永远不是项目。记忆、skills、worktree setup 配置都按项目走。

**运行位置**：一个选择器，两个值。

- 「本机 · 主目录」：任务直接改你手上的文件。改动基线就是 `HEAD`，收口只有提交；不要的改动按文件还原。不给「全部丢弃」，因为分不清哪些是任务改的、哪些是你自己没提交的。
- 「本机 · worktree」：任务在 `<dataDir>/worktrees/<id>` 的独立检出里干活，分支 `vgent/<id8>`，从项目**已提交的 HEAD** 开出，不带你未提交的改动，选择器里要明说。创建后跑项目的 setup 脚本。收口有提交、开 PR、带回主目录、丢弃。

**改动**：任务相对**任务基线**的 diff。worktree 任务的基线是 `workspace.baseCommit`，所以任务内提交过的、没提交的、未跟踪的都算。现状对的是 `HEAD`，agent 在 worktree 里一提交，改动就从界面上消失，这是 bug。

**模型**：用户唯一要选的「大脑」。引擎（Claude Code / Codex / 自研）是模型的实现细节，只作为模型选择器里的分组标题出现。任务有了对话之后不能跨引擎换模型，选择器里其它组置灰并说明原因。

**运行模式**：全局设置，三档，一一对应 harness 的权限模式：询问（allow-reads）/ 自动改文件（allow-edits）/ 全自动（allow-all）。外加一份全局 allowlist。审批卡上的「一直允许」写进 allowlist，不再是任务私有。因为是全局的，粒度必须细：条目要么是一个工具名，要么是 `bash(<命令>)`（如 `bash(git)`）；一条 shell 命令的每一段都在名单或内置安全清单里才免审，解析不了的命令不给「一直允许」。任务头和空状态不再有权限下拉。

**计划**：Plan 模式的产物，一份属于任务的 markdown，存 `<dataDir>/plans/<threadId>.md`，人可以直接改，Build 时原样交给 Agent 模式。

## 引擎能力表

界面显示什么由这张表决定，由 server 在 `GET /api/engines` 里下发；web 里不允许再写 `engine === "vgent"` 这种判断。

| 能力 | Claude Code | Codex | 自研 |
| --- | --- | --- | --- |
| 审批（能「询问」） | ✓ | ✗ 只能全自动 | ✓ |
| 提问 askUserQuestions | ✗ | ✗ | ✓ |
| 计划 / 待办 | ✓ TodoWrite | ✓ update_plan（目前不出 UI 部件） | ✓ updatePlan |
| Plan 模式 | ✓ 只读 + 提示词 | ✗（不能只读） | ✓ 只读工具 + 提示词 |
| 压缩上下文 | 引擎自管 | 引擎自管 | ✓ 手动 + 超预算裁剪 |
| 默认模型可知 | ✗ | ✗ | ✓ |
| MCP / skills / 记忆 | ✗ 未接 | ✗ 未接 | ✓ |

能力缺失的处理原则：**明说，不装**。例：运行模式是「询问」而选了 Codex 的模型，聊天框上方一行提示「Codex 不支持审批，这个任务会全自动运行」，而不是摆一个点不了的下拉。

## 现状对照

| 步 | 有 | 缺 / 错 |
| --- | --- | --- |
| 1 派活 | 空状态只剩四个选择：项目、运行位置（M2）、模型（按引擎分组，选模型即选引擎）、思考等级；运行模式和 allowlist 全局化（M3）；假按钮已清（M2）；模式 chip 是真的，Agent / Plan，⇧Tab 切换（M4） | 「只选模型」只做到一半：选择器按引擎分组，同一个 GPT-5.5 在 Codex 组和 Vgent 组各出现一次、能力不同，用户还是得懂引擎才会选 |
| 2 计划 | Plan 回合强制只读，最后的回复存成任务的计划文档；「计划」tab 上方是文档（可编辑、可保存）+ Build，下方仍是待办（M4） | Codex 不支持（能力表里写明，chip 置灰说明原因）；恢复 checkpoint 不回滚计划文档 |
| 3 执行 | 三引擎、审批卡、提问卡、子代理、记忆；worktree 建好后跑项目的 setup 脚本（M2）；「一直允许」按命令写进全局 allowlist（M3）；拒绝审批后回合自己结束（修了 harness 引擎上一直存在的卡死） | `bash(git)` 这种条目同时放行 `git status` 和 `git push`，还没细到子命令 |
| 4 纠偏 | 停止；运行中回车 = 排队，队列在 server 上，回合正常结束自动发下一条，可改可删，暂停时可手动发（M5）；草稿按任务存本地，切任务、刷新都在（M5）；每轮开跑前打 checkpoint，用户消息上「恢复到此处」，可撤销（M5） | 空闲时直接发送如果撞上 409，草稿还是会丢（发送路径是先清后发） |
| 5 验收 | 「审查 +N −M」、diff、按文件还原，全部对任务基线算（M1） | **主目录任务的基线还是 `HEAD`，不是任务开始时的状态**：仓库里本来就有你没提交的改动时，新任务一建出来就显示「审查 +N」并落进「待验收」，其实它什么都没改 |
| 6 收口 | 提交、开 PR、带回主目录、全部丢弃；收口结果显示在任务头、侧栏行和动作条（M1） | **主目录任务点「提交」是 `git add -A`，会把你自己没提交的改动一起提交进去**（同一个根因：主目录任务没有真正的任务基线；现在有 checkpoint 了，应该用任务的第一个 checkpoint 当基线，改动和提交都只算任务动过的路径）；新一轮对话会清掉收口结果，已开的 PR 链接随之从界面消失 |
| 7 归档 | 侧栏行菜单归档 / 取消归档 / 删除，归档顺带回收 worktree；「待验收」「已归档」分组（M1）；worktree 上限 25、自动回收最旧的（M2） | 上限还没有设置界面（M3 的设置页里做） |

## 工作计划

每个里程碑结束都从 main 打包装到 /Applications，并在这里更新状态。

**M1 收口** — 已完成，2026-09-18 落 main，验收标准逐条在浏览器里实测通过

- 改动基线改为任务基线；主目录任务仍对 `HEAD`。
- diffs 视图底部动作条：提交（信息预填任务标题，可改）、开 PR（仅当有 remote 且 `gh` 可用，否则不显示并说明原因）、带回主目录（三方合并式应用到主检出的工作区，有冲突就整体不动并列出冲突文件）、全部丢弃（二次确认）。
- `outcome` 落盘，侧栏和任务头显示「已提交 / PR #n / 已带回 / 已丢弃」。
- 归档与删除：侧栏行的右键菜单；归档顺带回收 worktree；「待验收」「已归档」两个分组。
- 验收标准：worktree 任务改文件，agent 自己提交一次，变更面板仍然显示全部改动；点「带回主目录」后主检出出现同样的未提交改动；归档后 worktree 目录消失、任务进「已归档」、恢复后一切回来。

**M2 在哪跑** — 已完成，2026-09-18 落 main，验收标准实测通过（本仓库的克隆里新 worktree 任务 setup 后 `pnpm build && pnpm test` 全绿）

- 一个「运行位置」选择器取代「本机」chip 和 worktree 开关；聊天框上方的位置标签显示真实位置。
- worktree setup：读项目里的 `.vgent/worktrees.json`，没有再读 `.cursor/worktrees.json`，同一套 schema（`setup-worktree-unix` / `setup-worktree`，环境变量 `ROOT_WORKTREE_PATH`；值是数组 = 命令列表，是字符串 = 相对配置文件的脚本路径）；输出进终端 tab；失败给警告不拦任务。
- worktree 上限（默认 25）和自动回收最旧的非运行任务。
- 假按钮清零：「+」打开 `@` 文件补全；「规划一个想法」「打开编辑器」在对应功能做出来之前先删。
- 验收标准：本仓库配 `pnpm install --frozen-lockfile` 后，新 worktree 任务里 `pnpm test` 能跑。

**M3 模型在前，运行模式全局化** — 已完成，2026-09-18 落 main，验收标准实测通过

- 模型选择器按引擎分组，选模型即选引擎；任务头和空状态去掉引擎 pill 和权限 pill。
- 设置页：运行模式三档 + allowlist；默认模型。
- `GET /api/engines` 下发能力表，web 清掉按引擎名的判断。
- 验收标准：空状态只剩项目、运行位置、模型、思考等级四个选择；Codex 模型在「询问」模式下有明示。

**M4 Plan 模式** — 已完成，2026-09-18 落 main，验收标准实测通过（Claude Code 和自研引擎各走一遍）

- 模式 chip 变真：Agent / Plan，⇧Tab 切换。Plan 回合只读运行，产出写入任务的计划文档；右栏「计划」显示文档（可编辑）+ Build 按钮。
- 验收标准：Plan 出计划，手改一行，Build 后 agent 按改过的计划执行。

**M5 纠偏** — 已完成，2026-09-18 落 main，验收标准实测通过

- 运行中 Enter = 排队，回合结束自动发出，可删可改；草稿任何情况下不丢（按任务存在本地，切任务、刷新都在）。
  - 队列存在 server 上、属于任务，关掉窗口也照样往下发。
  - 只有回合正常结束（回到空闲）才自动发下一条。停在等审批 / 等回答时不发，否则会顶掉那次审批；被你手动停止或出错时队列原地暂停，由你决定继续发、改还是删。
  - 聊天框上方的排队条叫「排队」；右栏原来叫「队列」的 tab 其实是待审批和待回答，改名「待处理」。
- checkpoint：每个由用户消息开始的回合，开跑前给工作目录打快照（git 对象，不碰你的暂存区和 HEAD），日志里每条用户消息旁有「恢复到此处」，只回退文件不删消息。
  - 只管 git 看得见的文件；被忽略的（node_modules、构建产物）不动。不是 git 仓库的项目没有 checkpoint。
  - 恢复前先给当前状态再打一个快照，所以恢复可以撤销。主目录任务的恢复会连你自己之后改的文件一起回退，确认时明说。
- 验收标准：运行中排两条，依次执行；恢复到第一条之前，文件回到当时状态。
